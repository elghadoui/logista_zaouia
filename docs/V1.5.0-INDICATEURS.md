# V1.5.0 — dictionnaire des indicateurs

## Périmètre commun

Les tableaux sont en lecture seule sous les permissions existantes `receptions` et `caisserie`. Il n'est pas nécessaire de créer ni d'attribuer des permissions supplémentaires. Un utilisateur sans le droit Voir correspondant n'accède ni à la page ni aux API/exports. Le menu Opérations existant est conservé.

Contexte choisi dans les exercices autorisés de l'utilisateur ; station ZAOUIA ou DIAF uniquement, code local obligatoire. En consolidé les deux contextes sont résolus/autorisés avant lecture. Deux sources disponibles doivent porter les mêmes dates et libellé de campagne. Tout échec de source est visible ; `totalKg=null`, `complete=false`, `observedKg` reste seulement un sous-total observé. Les données ne sont jamais copiées entre stations.

Une dimension absente dans une réception est conservée avec un libellé inconnu. Un net manquant ou une date non exploitable rend le total incomplet. Le compteur de dates manquantes concerne tous les en-têtes de station répondant aux filtres hors date : leur rattachement à une période ne peut être inventé.

## Filtres et temps

Heure métier : Africa/Casablanca. Aujourd'hui, hier, 7 jours (aujourd'hui + six jours précédents), mois jusqu'à aujourd'hui, semaine depuis lundi jusqu'à aujourd'hui, campagne complète, période personnalisée du/au inclus. Bornes SQL : >= début et < lendemain de la fin, avec intersection des bornes campagne.

Tous les widgets de réceptions et de mouvements utilisent le même filtre station/exercice/catégorie/produit/variété/producteur/verger/type caisse/recherche et la même période. Les cartes aujourd'hui/hier/7 jours/mois sont des sous-intersections du filtre de date sélectionné ; par exemple Hier vaut zéro si le filtre ne garde qu'aujourd'hui. La carte « Campagne / période filtrée » affiche la somme sur l'intersection demandée, pas un cumul hors filtres.

Le bouton d'une carte choisit sa période et ouvre les détails. Les barres quotidiennes/hebdomadaires limitent les détails à la date/semaine. Le classement d'un producteur ou d'une variété ouvre la station de la ligne pour ne pas supposer que le même code représente la même personne dans une autre station.

Catégorie = culture ; produit = groupe de variétés. Aucun produit ne se limite aux agrumes. Le filtre mouvement E/S est propre à la caisserie. Les choix de référence sont issus des enregistrements réels du contexte ; jusqu'à 3 001 choix par dimension, avertissement au-delà de 3 000.

## Réceptions

| Indicateur | Calcul |
|---|---|
| Net sélectionné | SUM(reception.netrec) des en-têtes filtrés ; /1000 pour tonnes |
| Aujourd'hui / hier / 7 jours / mois | Même somme, intersection avec la fenêtre indiquée |
| Lots | COUNT(*) des en-têtes, identité contexte/station/numrec ; pas de jointure de détails |
| Producteurs distincts | COUNT(DISTINCT verger.refadh) dans chaque source ; les inconnus NULL ne sont pas une personne |
| Variétés distinctes | COUNT(DISTINCT reception.codvar) dans chaque source |
| Consolidé | Addition des kg des deux sources compatibles et complètes ; aucun DISTINCT global sur numrec |
| Producteurs/variétés en consolidé | Somme des identités station/contexte/code ; explicitement libellés « · station », pas une déduplication de personnes interstation |
| Variation période précédente | Même filtre métier, fenêtre immédiatement précédente de même nombre de jours, bornée à la campagne ; (actuel−précédent)/précédent ×100 ; non comparable si précédent nul |
| Quotidien | Groupe par dterec ; détail accessible par barre |
| Hebdomadaire | YEARWEEK(dterec,3), année ISO, lundi–dimanche ; compte des lots et kg |
| Variation hebdomadaire | Semaine ISO immédiatement précédente disponible dans le filtre ; pas de comparaison entre semaines non contiguës ; partiel si borne de filtre coupe la semaine |
| Variétés / producteurs | Somme des kg + compte des en-têtes par source et code, ordre décroissant |
| Part variété | Kg du groupe / net observé du périmètre ; ne constitue pas un pourcentage de source manquante |
| Contribution station | Kg station / kg observés disponibles ; total incomplet signalé si nécessaire |

## Campagnes et archives

L'utilisateur choisit les archives existantes autorisées (lecture seule), une par station. La comparaison consolidée exige les deux. Aucun nom de base d'archive n'est deviné. L'archive doit précéder la campagne courante sans chevauchement, avec une année de début précédente. Les deux archives doivent être compatibles entre elles.

La fin courante est limitée à aujourd'hui lors d'une comparaison pour éviter d'opposer le réalisé à une campagne entière. Chaque date sélectionnée est décalée du **même nombre de jours depuis le début de campagne**. Les données restent bornées à la fin de l'archive. Les semaines ISO sont affichées selon l'année de chacune ; elles ne sont pas alignées arbitrairement par numéro de semaine. Le tableau « Jour campagne » compare dates/jours écoulés et cumuls ; les séries ISO et classements de chaque archive restent consultables séparément.

Variation campagne = (net actuel comparable−net archive comparable)/net archive ×100, seulement si toutes les sources sont complètes et archive non nulle. Une archive indisponible ne produit pas de variation inventée.

## Estimations

Arbres × estimation kg/arbre /1000 pour les parcelles renseignées positives et sans tuple métier ambigu. Couverture = parcelles exploitables / parcelles du périmètre du référentiel. Liste des incomplètes/ambiguës limitée à 100 ; décompte complet affiché.

Il s'agit d'un panneau référentiel explicitement distinct : les filtres culture/groupe/variété/producteur/verger/recherche s'appliquent ; dates et caisses ne décrivent pas une parcelle. Aucun rattachement de campagne prouvé ; pas d'écart ni taux de réalisation. Estimation consolidée désactivée faute de correspondance interstation démontrée. Une absence n'est jamais un zéro de production.

## Caisserie

Nombre de mouvements, quantités brutes par type de caisse et E/S, dtecai et clé numcai. Sans type de caisse sélectionné, les graphiques temporels et classements affichent des nombres de mouvements ; après choix d'un type, ils affichent ses quantités. Le tableau par type conserve toujours les quantités séparées. Quantités de types différents non interchangeables ; le détail conserve systématiquement le type. Pas de total de stock physique ni dette/producteur/personnel, pour les raisons de l'audit. Les regroupements temporels indiquent des flux bruts, pas une disponibilité.

## Exports et pagination

Tri SQL sur liste blanche : date, numéro, producteur, variété, poids net/quantité. Ordre stable avec station/contexte/numéro comme départage. Pagination 25 lignes ; fusion serveur de deux sources sur le préfixe nécessaire. Les tableaux de bord ne renvoient pas au navigateur toutes les lignes préchargées pour cette fusion.

Excel `.xlsx` : détails filtrés complets (jusqu'à 20 000 lignes au total, refus au-delà), kg et tonnes numériques, dates Excel typées, en-têtes figés, filtre de colonnes et onglet Contexte avec filtres/périodes/limites. Les libellés commencent éventuellement par =, +, − ou @ sans devenir une formule : ils restent des cellules texte. Un export refusé ou incomplet n'est pas téléchargé silencieusement.
