# Mise à jour VITASOUSS 1.5.0 et retour arrière

## Prérequis

Installation existante **VITASOUSS 1.4.1 + Drencher 1.3.2.1**, avec migrations Drencher 010/011 et réservations déjà initialisées. Cette mise à jour enrichit les tableaux de bord et conserve Drencher 1.3.2.1.

Pas de migration SQL requise, ni métier ni administrative. Ne pas rejouer les migrations 010/011/012 et ne pas réinitialiser les réservations. Aucun compte, mot de passe ou droit ne doit être réinitialisé. Les nouveaux liens réutilisent Voir/Réceptions et Voir/Caisserie ; aucun droit nouveau automatiquement attribué.

Le compte MySQL de chaque contexte doit pouvoir lire les tables analytiques existantes : entreprise, reception, caisserie, typecaisse, verger, adherent, variete, culture, grpvar et, pour les estimations, parcelle. Aucun privilège d'écriture supplémentaire n'est nécessaire. Si une permission SELECT manque, faire vérifier les droits de lecture par votre administrateur ; ne pas élargir automatiquement les droits du compte.

Lire l'audit et les limitations avant de considérer la caisserie comme un outil de stock : cette version ne prétend pas calculer les soldes non démontrés par les données.

## Installation manuelle sur VM-APPS

1. Sauvegarder le dossier IIS existant, les configurations, clés Data Protection et secrets, avec leurs ACL, selon votre procédure habituelle. Garder aussi la sauvegarde de base habituelle ; cette livraison ne touche aucun schéma.
2. Extraire le ZIP dans un dossier de préparation **distinct** de `C:\Apps\VitasoussReferentiels`. L'archive contient `update/`, `docs/` et `sql/` informatif.
3. Prévoir une fenêtre courte et arrêter **uniquement** le pool IIS VITASOUSS concerné. Conserver l'identité svc_vitasouss. Aucun nom de pool n'est supposé par la livraison.
4. Copier de façon additive les fichiers de `update/` vers `C:\Apps\VitasoussReferentiels`. Aucun `/MIR`, aucune suppression d'anciens assets ou de dossiers locaux. Le paquet n'inclut pas web.config, appsettings*.json, clés ou secrets.

Exemple PowerShell, **adapter uniquement le dossier d'extraction** après sauvegarde et arrêt du pool :

```powershell
$sourceUpdate = 'C:\Temp\VITASOUSS-V1.5.0\update'
$destinationApp = 'C:\Apps\VitasoussReferentiels'
if (-not (Test-Path -LiteralPath "$sourceUpdate\Vitasouss.Api.dll")) { throw 'Mise à jour introuvable' }
robocopy $sourceUpdate $destinationApp /E /COPY:DAT /R:2 /W:2 /XF appsettings*.json web.config /XD keys secrets logs assistant-audit
if ($LASTEXITCODE -ge 8) { throw 'Échec de copie : ne pas redémarrer avant vérification' }
```

5. Redémarrer le même pool, sans changer identité, authentification, configuration IIS ni ACL.
6. Vérifier `http://192.168.1.253:8081/api/health` : version **1.5.0**, drencherVersion **1.3.2.1**. Recharger complètement le navigateur (Ctrl+F5).
7. Avec Admin, vérifier les contextes et archives existants : local_refsta, bases/serveurs corrects et entreprise active portant des dates valides. Ne pas déduire la station depuis la table station du dump.

## Recette rapide

- Compte autorisé Réceptions : nouveau menu Tableaux de bord/Réceptions ; compte sans droit : aucun lien/accès direct.
- Même contrôle pour Caisserie. Les anciens menus Opérations restent accessibles avec leurs mêmes droits.
- Vérifier les tonnages sur une période connue, les filtres et les détails/export ; netrec seul fait foi.
- Consolider uniquement deux contextes de même campagne. Un utilisateur restreint à une station ne doit pas pouvoir ajouter la deuxième.
- Choisir des archives réellement autorisées pour comparer les jours écoulés. Confirmer les limites et les périodes effectives affichées.
- Vérifier les panneaux Caisserie « Non déterminable » et les flux par type ; ne pas les interpréter comme stock disponible.
- Vérifier le panneau d'estimations partielles et son absence de taux de réalisation.
- Hicham : Nouveau cycle et édition de ses brouillons, pas de gestion programmes/qualité. Mbark/Samira : qualité/programmes selon leurs droits. Admin : droits exceptionnels conservés. Ne pas effectuer ces essais avec des traitements de production fictifs ; utiliser votre contexte Recette isolé.
- Vérifier F04 et les cinq documents de stock sur un cycle de recette existant. Leurs sources restent identiques.

## Retour arrière

Arrêter le pool VITASOUSS, restaurer depuis la sauvegarde les **quatre fichiers serveur remplacés** et l'ancien `wwwroot/index.html` (et ses assets si nécessaire), puis redémarrer le même pool. La copie additive laisse les anciens assets disponibles. Ne pas restaurer une configuration locale ancienne par accident ; conserver les clés et secrets en place avec leurs ACL. Aucun SQL inverse ni suppression de données nécessaire. Vérifier la santé 1.4.1 / Drencher 1.3.2.1 puis Ctrl+F5.

La livraison ne déclenche aucune installation ni connexion aux VM. Les sources complètes sont fournies séparément, sans configurations privées ni dump de données.
