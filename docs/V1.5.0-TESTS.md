## Limites des essais

Lecture réelle uniquement de la **copie** fournie ZAOUIA. DIAF et archives réellement exploités sur les VM non testés ; scénarios correspondants synthétiques. Aucun test de charge sur production ni installation IIS réalisée. SSR ne constitue pas un test de clics navigateur ou d'impression papier ; ces éléments ne sont pas revendiqués sans un rapport distinct.

Les échecs intermédiaires ont permis de corriger la matérialisation des dates MySqlDateTime, le regroupement strict des semaines ISO et les collations des choix. Un problème de sql_mode du générateur de fixtures a été corrigé ; les données de la copie importée n'ont pas été modifiées. Les chiffres de cette table proviennent des passes réussies, pas de ces essais préliminaires.

NuGet signale les avertissements existants NU1902/NU1903 détaillés dans les limitations. Les compilations aboutissent ; ces avertissements ne sont pas masqués.

## Reproduction

Dans le dossier source, avec SDK .NET 10, Node et MySQL 5.7 de test local préparés :

```powershell
dotnet run --project tests/AnalyticsTests -c Release
dotnet run --project tests/DrencherPermissionTests -c Release
dotnet run --project tests/AssistantTests -c Release
node tools/verify-v150-ui.mjs
node tools/verify-drencher-v1321-ui.mjs
node tools/verify-v150-api.mjs
node tools/verify-drencher-v150-api.mjs
node tools/verify-drencher-v150-guard.mjs
```

Les tests SQL refusent tout serveur métier différent de 127.0.0.1:33307. Fournir uniquement le mot de passe applicatif **fictif** local via VITASOUSS_TEST_PASSWORD pour les scripts HTTP ; ne jamais adapter les garde-fous pour les VM. La copie du dump et les configurations privées restent hors archives sources et IIS.
